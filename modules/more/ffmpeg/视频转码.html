视频格式对比 ​

📊 视频编码核心指标对比 ​

编码格式压缩效率（相比H.264）画质表现硬件支持专利授权典型应用场景
H.264/AVC基准（1.0x）中等全平台支持需MPEG-LA授权直播、视频会议、旧设备兼容
H.265/HEVC↑ 40-50%同码率下更优主流设备支持专利费高4K流媒体、蓝光视频
VP9↑ 30-40%接近HEVC安卓/Web广泛支持免版权费YouTube、WebRTC
AV1↑ 50-60%同码率最佳新设备逐步支持免版权费8K流媒体、未来标准

🎨 颜色标识说明 ​

  • 🔴 专利限制
  • 🟢 开源免费
  • 🔵 广泛兼容
  • 🟡 新兴技术

  1. 压缩效率测试条件

    • 测试分辨率：1080p → 4K
    • 码率范围：2Mbps ~ 50Mbps
    • 工具：FFmpeg + libvpx（VP9）/ libaom（AV1）

  2. 画质评估标准

    • VMAF > 90（主观视觉质量）
    • PSNR > 40dB（客观指标）

  3. 硬件支持关键时间节点

    芯片平台AV1解码支持世代
    Intel第11代酷睿（2020）
    NVIDIARTX 30系（2020）
    高通骁龙8 Gen1（2021）

音频采样频率转换（转为 48kHz） ​

bash
ffmpeg -i input.mp4 -c:v copy -ar 48000 -c:a aac output.mp4

视频编码转换（转为 av1） ​

bash
ffmpeg -i input.mp4 -c:v libaom-av1 -crf 30 -b:v 0 -c:a copy output.mp4

视频转码：vp9 => h.264 ​

-c:v libx264: 使用 H.264 视频编码
-crf 23: 画质控制（18-28，数值越小画质越好）
-c:a aac: 音频编码为 AAC
-movflags +faststart: 支持网页流式播放
bat
ffmpeg -i input.webm -c:v libx264 -preset fast -crf 23 -c:a aac -movflags +faststart output.mp4

视频转码：vp9 => h.265 ​

参数	含义
-i input.webm	输入 VP9 文件（可能是 .webm 或 .mp4 容器）
-c:v libx265	使用 H.265（HEVC）编码视频
-preset medium	编码速度（越慢压缩越好，常用有 ultrafast 到 veryslow）
-crf 28	质量（范围 18-51，越小越清晰，23 是 H.264 推荐，H.265 通常设在 26-28）
-c:a copy	音频流不重新编码（原样复制）
你也可以改为 -c:a aac 来重编码音频，增加兼容性。
bat
ffmpeg -i input.mkv -c:v libx265 -preset medium -crf 28 -c:a copy output.mp4

视频转码：vp9 => AV1 ​

-c:v libaom-av1	使用 AV1 编码器（还可以用 libsvtav1，速度更快）
-crf 30	推荐值（28~35），数值越小越清晰
-b:v 0	表示只用 crf 控制码率（常用于 AV1）
-c:a libopus 用 Opus 编码音频（AV1 常配合 MKV 容器）
-SVT-AV1 默认 preset 是 8（非常快，压缩效果差）, 建议设置为 6 或 4，压缩更高，但速度会变慢
bash
ffmpeg -i input.mkv -c:v libsvtav1 -crf 30 -b:v 0 -c:a libopus output-av1.mp4
ffmpeg -i input.mkv -c:v libsvtav1 -crf 37 -preset 6 -b:v 0 -c:a libopus output-av1-2.mp4
